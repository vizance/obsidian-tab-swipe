## Context

本 repo 目前只有 Spectra 骨架與 git 設定，沒有任何外掛程式碼、建置流程或測試環境。本次變更同時要建立可建置、可用 BRAT 安裝的最小外掛，以及第一個功能。

Obsidian 手機版在畫面底部提供一條導覽列，上面有返回、前進、搜尋、新增、分頁數與選單共六顆按鈕。切換分頁必須點開分頁數按鈕、展開清單、再點目標。這條導覽列在 DOM 上以 `.mobile-navbar` 這個 class 呈現，屬於 Obsidian 內部結構，官方沒有承諾其穩定性，這是本設計最主要的外部限制。

社群外掛市集現有 6695 個外掛中沒有等效方案。Mobile UX 需要先按住浮動按鈕再拖曳畫出形狀；Mobile Tab Bar 增加一條常駐分頁列且仍需點擊。前者動作更多，後者佔用畫面且沒有解決「手指不離開就切換」。

## Goals / Non-Goals

**Goals:**

- 在手機版導覽列上水平滑動即可切換到相鄰分頁，一次一格
- 導覽列既有六顆按鈕的點擊行為完全不受影響
- 分頁切換邏輯只使用 Obsidian 官方公開 API，不依賴未公開入口
- 手勢判定與分頁計算可在沒有 Obsidian 執行環境的情況下單元測試
- 產出可透過 BRAT 安裝到實機的建置產物，讓門檻手感能被真正驗證

**Non-Goals:**

- 不做快速連續滑動跳多格
- 不做滑到底自動叫出分頁清單
- 不做任何切換提示，包含 toast、震動與轉場動畫
- 不提供設定畫面，門檻先以常數寫死
- 不在編輯區或其他區域偵測手勢
- 桌面版不提供任何功能
- 不處理左右側欄內的分頁

## Decisions

### 感應區只綁定手機導覽列

在 `.mobile-navbar` 元素上掛載 touch 監聽，不碰編輯區。

替代方案一是整個編輯區橫滑，被否決的原因是它同時與 Obsidian 內建的邊緣滑動開側欄、文字選取、表格橫向捲動三件事衝突。替代方案二是在螢幕底部疊一層自訂透明感應帶，面積大且不依賴內部 class，但必須自行處理點擊穿透，且誤觸率明顯高於前者。

選導覽列的理由是它語意上本來就是導航區域，在上面左右滑與既有功能語意一致，而且與編輯行為零重疊，誤觸成本最低。代價是元素高度只有約 50 px，且依賴 Obsidian 內部 class。

### 手勢方向對應與循環切換

手指向左滑切換到排列順序中右邊的分頁，向右滑切換到左邊的分頁，方向對應與相簿、瀏覽器分頁一致。

到達兩端時循環：位於最後一個分頁再向左滑回到第一個，位於第一個分頁再向右滑到最後一個。

替代方案是停在邊界不動。被否決的原因是常態分頁數為 2 到 3，循環讓任何一個分頁都在一次滑動內可達；停住則需要額外的邊界回饋機制才不會讓使用者困惑，而本設計已決定不做任何提示。Obsidian 桌面版的分頁循環行為同樣是繞回的，保持一致。

### 用官方公開 API 自行計算分頁順序

以 Workspace 的 iterateRootLeaves 蒐集根區分頁的排列順序，比對目前作用中的 leaf 取得索引，再以 setActiveLeaf 搭配 focus 參數切換。

替代方案是直接呼叫內建命令 workspace:next-tab。程式碼最短，但那是官方沒有公開的入口，其存在與否隨版本變動，且它的循環行為不由本外掛決定。

選公開 API 的理由是循環規則必須掌握在本外掛手上，而且公開 API 的破壞性變更頻率遠低於內部入口。代價是多寫十餘行索引計算。實作前需先確認安裝版本的型別定義中這些方法的實際簽名。

### 滑動與點擊的判定門檻

在 touchstart 記錄起點座標，touchend 時計算位移。同時滿足水平位移絕對值大於等於門檻、且水平位移絕對值大於垂直位移，才判定為滑動並觸發切換，此時才呼叫 preventDefault。任一條件不滿足就完全不干預，讓導覽列按鈕的點擊自然發生。

門檻起始值為 40 px，集中定義在單一常數，實機微調後回填。多指觸控直接忽略，只處理單指。

第一版不設時間上限。長按後緩慢拖曳是否需要排除，留待實機觀察。

### 手勢偵測層與分頁切換層分離

手勢層只輸出方向，型別為前一個、後一個或無，它完全不知道 Obsidian 有分頁這件事。切換層接收方向並執行實際切換，它不知道方向從哪裡來。

這條接縫的價值在於兩層都能獨立測試：手勢層可用合成的座標序列驗證門檻與軸向判定，切換層可用假的 workspace 物件驗證索引計算與循環。若兩層合併，門檻邏輯就必須在有 Obsidian 執行環境時才能測。

刪除測試：移除手勢層，外掛沒有輸入來源，功能歸零；移除切換層，偵測得到方向但不會有任何事發生。兩層都藏有實質邏輯，不是轉手用的包裝。

### 桌面不掛載與缺少元素時靜默停用

Platform 判定非行動裝置時，載入流程直接結束，不註冊任何監聽。找不到導覽列元素時同樣不掛載，不顯示錯誤也不通知使用者。分頁數小於等於一時，手勢仍會被辨識但切換層回傳無動作。

理由是外掛不應該因為 Obsidian 改版就在使用者畫面上噴錯。這個限制需要寫進 README，做法比照 Mobile Tab Bar 對其外部依賴的公開說明。

## Implementation Contract

**可觀察行為**

使用者在手機版底部導覽列上水平滑動超過門檻，作用中分頁切換為排列順序上的相鄰分頁，兩端循環。導覽列六顆按鈕的點擊行為與變更前完全相同。桌面版行為完全不變。

**介面與資料形狀**

- 手勢層匯出一個判定函式，輸入為觸控起點與終點座標，輸出為方向值：前一個、後一個，或無。
- 切換層匯出一個切換函式，輸入為 workspace 物件與方向值，輸出為被啟用的 leaf，無可切換對象時輸出空值。
- 外掛入口在載入時註冊監聽、在卸載時移除所有監聽，不留殘餘事件。

**失敗模式**

- 找不到導覽列元素：靜默不啟用，不拋錯、不通知。
- 分頁數小於等於一：切換函式回傳空值，畫面無變化。
- 多指觸控：忽略該次觸控，不判定為滑動。
- 桌面環境：完全不註冊監聽。

**驗收條件**

1. 執行建置指令後產出 main.js，且在 Obsidian 手機版可載入不報錯。
2. 手勢層單元測試涵蓋五種情境：位移不足、垂直位移為主、多指觸控、向左滑、向右滑。
3. 切換層單元測試涵蓋四種情境：單一分頁、三分頁向後切換、三分頁向前切換、兩端循環各一次。
4. 實機以 BRAT 安裝後驗證三件事：導覽列六顆按鈕逐一點擊皆正常運作；左右滑各切換一格且方向正確；桌面版載入後不影響任何既有操作。

**範圍邊界**

- 在範圍內：外掛骨架與建置設定、手勢偵測、分頁循環切換、上述單元測試、README 與授權檔。
- 不在範圍內：設定畫面、快滑連跳、分頁清單、切換提示、側欄分頁、桌面功能、Release 發布自動化。

## Risks / Trade-offs

- 依賴 Obsidian 內部 class `.mobile-navbar`，改版可能失效 → 選擇器集中在單一常數，找不到即靜默停用，並在 README 明確標示此限制
- 門檻值不合手感會造成想點按鈕卻切了分頁 → 門檻集中在單一常數方便微調，第一版取偏保守的 40 px，並以實機驗收條件把關
- 呼叫 preventDefault 可能影響導覽列原生行為 → 僅在確定判定為滑動的分支才呼叫，其餘路徑完全不干預
- 分頁順序來源可能包含非預期的 leaf → 以單元測試鎖定期望的順序與數量，必要時在切換層過濾
- 只有兩到三個分頁時，循環與非循環差異不明顯，可能過度設計 → 循環的實作成本是一次取餘數運算，不構成額外複雜度

## Migration Plan

首次發布，沒有既有使用者需要遷移。建置產物 main.js 不進版控，透過 GitHub Release 附上 main.js 與 manifest.json 供 BRAT 安裝。若手勢造成誤觸無法接受，回退方式是在 Obsidian 設定中停用外掛，停用後導覽列立即恢復原生行為。

## Open Questions

- 滑動門檻的最終數值，需實機微調後回填至常數與 README
- 使用者開啟分割視窗時的分頁順序如何呈現，第一版沿用預設順序，並在 spec 中標明此限制
- 是否需要加入時間上限以排除長按後的緩慢拖曳，待實機觀察後決定
